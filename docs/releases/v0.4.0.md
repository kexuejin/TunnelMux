# TunnelMux v0.4.0

TunnelMux `v0.4.0` is the embedded-daemon and control-plane hardening release. The desktop app now owns the daemon in-process, multi-tunnel operations are isolated end to end, and the release path fails closed on authentication, persistence, updater, and packaging errors.

## Highlights

- **Single-owner desktop runtime**: the GUI hosts `tunnelmuxd` in-process, stops the tunnels and provider processes it owns on exit, and leaves an adopted external daemon running.
- **Tunnel-scoped control plane**: routes, access gates, runtime state, logs, diagnostics, and CLI operations consistently carry a tunnel scope.
- **Security boundaries**: loopback-only token discovery, bearer-protected control endpoints, upstream credential stripping, OS credential storage, and no API-level provider executable override.
- **Lifecycle consistency**: per-tunnel operation generations, cancellation-aware teardown, single-writer persistence, atomic owner-only state writes, and explicit persistence errors.
- **Hardened data plane**: bounded health checks, rate limiting, safer header forwarding, streaming and WebSocket support, and mounted-app rewriting for `/api` and `/plugins` paths.
- **Verified updater**: SHA-256 is mandatory; archive names, semver, response size, timeout, traversal, and native-bundle boundaries are checked before installation.
- **New console UX**: Overview, Services, Tunnels, Diagnostics, and Settings views with a persistent sidebar and semantic light/dark themes.
- **Release integrity**: sidecar-free packaging, least-privilege workflow permissions, CI contract tests, release-manifest verification, and RustSec auditing.
